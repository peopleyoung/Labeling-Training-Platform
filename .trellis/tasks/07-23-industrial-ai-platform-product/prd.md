# 工业质检训练平台产品化

## Goal

在现有高保真原型基础上开发可持续迭代的工业质检模型生产平台，使算法工程师和数据人员能够以真实、持久化的数据完成数据集管理与标注、训练任务创建与追踪、模型资产管理和部署格式转换。

## Background

仓库已经具备 React + TypeScript + Vite 前端原型，覆盖工作台、数据集、矩形/多边形/关键点标注、四步训练向导、训练监控、模型仓库和 ONNX/TensorRT/TorchScript/OpenVINO 转换。现有业务状态集中在 `AppContext` 和类型化 mock 数据中，刷新后会恢复种子数据，尚无后端、数据库、对象存储、鉴权或真实任务执行器。

本阶段不是重做原型，而是沿用现有工业质检信息架构、科技蓝视觉和交互路径，建立可运行的产品基础。

## Requirements

- R1：保留现有关键路由、中文界面和工业质检工作流，产品化改造不得破坏已通过验收的核心交互。
- R2：建立版本化 HTTP API 和统一错误契约，前端通过服务层访问产品数据，不再直接依赖 mock 状态。
- R3：使用关系数据库持久化数据集、数据集版本、类别、标注任务、标注对象、训练任务、模型版本和转换任务。
- R4：图片、导出包、训练产物和转换产物通过对象存储抽象管理；本地开发环境应能独立运行。
- R5：标注保存应支持矩形、多边形和关键点结构，包含图像、类别、坐标、状态和修订时间，并提供并发更新保护。
- R6：数据集导出应形成可追踪的异步任务，支持 YOLO、COCO、VOC、COCO Segmentation、PNG Mask 和 COCO Keypoints 的执行器边界与产物记录。
- R7：训练创建覆盖目标检测、语义分割、关键点检测和 SDXL；服务端校验数据集兼容性、参数与资源配置，并生成可追踪任务。
- R8：训练与转换采用队列和执行器接口；首个产品增量可以使用可控的本地执行器模拟生命周期，但 API、日志、进度和失败状态必须是真实持久化的。
- R9：模型版本由成功训练任务产生或登记，保留来源、指标、框架、文件、状态和转换血缘。
- R10：转换任务支持 ONNX、TensorRT、TorchScript 和 OpenVINO，服务端校验格式、精度与目标硬件组合。
- R11：提供健康检查、结构化日志、统一配置、数据库迁移、种子数据和开发环境启动方式。
- R12：关键接口和跨层流程具备自动化测试，现有前端单元测试与端到端测试继续通过。
- R13：目标检测训练必须把已保存标注物化为标准 YOLO 数据集并真实执行 YOLOv5/YOLOv8；成功任务登记框架生成的 `best.pt` 和实际指标。YOLO 模型转换必须调用模型家族对应的真实导出器，禁止以占位二进制模拟 ONNX、TensorRT、TorchScript 或 OpenVINO 成功。
- R14：语义分割、关键点与 SDXL 不得再写入标记文件模拟训练。分割和关键点必须消费已保存标注、执行真实反向传播并登记可加载模型；SDXL 必须使用预置基础模型执行 GPU LoRA 类微调。每个模型家族只开放经过真实实现的转换格式。
- R15：创建数据集时不要求选择任务类型；数据集作为通用图像与标注容器，任务或格式兼容性延后到导出和训练任务创建阶段校验。
- R16：导出和训练阶段的“数据格式”指标准标注格式，而不是任务类型别名。格式选择必须持久化并真实控制数据物化/加载路径，不能只作为界面字段。
- R17：首版格式兼容矩阵为：目标检测训练/导出支持 YOLO、COCO、VOC；语义分割训练/导出支持 COCO Segmentation、PNG Mask；关键点训练/导出支持 COCO Keypoints。训练向导先选择任务类型，再只显示该任务兼容的数据格式。
- R18：COCO Keypoints 首版按“每张图片一个关键点实例”组织，图片内关键点按正整数编号排序并组合为一个对象；多实例关键点分组暂不开放。
- R19：标注工作台扩展为常规工业视觉标注工具，新增线段/折线、椭圆、图像标签和关键点骨架，并让矢量对象支持选择、移动、控制点编辑、隐藏和锁定；旧矩形、多边形、关键点标注文档必须无损读取。
- R20：SDXL 训练数据必须支持逐图人工 Caption、是否纳入训练和裁剪区域标注；保存、统一提交、审核和乐观锁应与几何标注共用同一文档生命周期。Image Folder 物化必须生成 `metadata.jsonl`，真实 Runner 优先消费已审核主 Caption，不再把几何类别拼接 Prompt 作为新任务的默认数据真源。
- R21：训练指标曲线必须提供可读的纵轴刻度与精确数据查看。质量指标使用左轴，Loss 使用右轴；悬浮或触摸数据点显示 Epoch 和各系列数值，系列可以通过图例切换显示。

### Supported Model Families

- 目标检测：YOLOv5、YOLOv8 系列。
- 语义分割：SegFormer、U-Net、DeepLabV3+ 系列。
- 关键点检测：HRNet、HigherHRNet 系列（用户输入中的 `hernet` / `higerhrnet` 按此解释）。
- 生成模型：SDXL 系列，首版覆盖 UNet LoRA 和 DreamBooth LoRA；ControlNet 在成对条件图数据契约落地前不开放。用户输入中的 `SDXLmox` 按“SDXL 模型”解释。

## Product Decisions Already Confirmed

- 面向工业质检场景。
- 标注采用真实绘制方案，支持矩形、多边形和关键点。
- 训练创建采用四步向导。
- 视觉采用浅色专业工作台和科技蓝主操作色。
- 训练类型为目标检测、语义分割、关键点检测和 SDXL。
- 转换目标为 ONNX、TensorRT、TorchScript 和 OpenVINO。
- 原型阶段不包含登录、组织、成员和权限；产品化首增量默认延续单工作空间，除非部署目标要求提前引入租户隔离。
- 首版部署采用企业内网、单租户一体化部署；前端、API、关系数据库、对象存储和任务 Worker 通过 Docker Compose 运行。
- YOLOv5/YOLOv8 采用 Ultralytics 的 AGPL-3.0 开源许可路径；平台交付接受对应源码开放、修改披露和网络使用场景的许可义务。
- 首版计算节点基线为 `2 × NVIDIA T4 16GB`；平台需要在这一资源上支持单卡/双卡任务分配和显存受限训练配置。
- 首版提供本地账户登录和单工作空间角色：管理员、算法工程师、标注员；关键写操作记录操作者和时间。

## Acceptance Criteria

- [ ] AC1：一条命令可启动前端、API、数据库、对象存储和任务工作进程的本地开发环境，并自动完成迁移与种子初始化。
- [ ] AC2：刷新浏览器后，数据集、标注、训练和转换任务仍从数据库恢复，核心页面不依赖静态 mock 作为业务真源。
- [ ] AC3：用户可以读取图像并保存矩形、多边形和关键点标注；重新进入标注页能恢复保存结果，并能识别并发修改冲突。
- [ ] AC4：完整格式矩阵的导出通过异步任务执行，能查询进度、失败原因和产物元数据，并只包含与所选格式兼容的已标注图片。
- [ ] AC5：四类训练任务可通过现有向导提交到后端，任务状态、日志、进度和指标可持续查询；执行器失败会被持久化并显示。
- [ ] AC6：成功模型可以创建四类转换任务，转换配置被校验，产物与源模型保持可追溯关系。
- [ ] AC7：API 具备可机器识别的校验错误、冲突错误和任务错误；前端显示可操作的中文反馈。
- [ ] AC8：数据库迁移、API 单测、执行器集成测试、前端类型检查/单测/构建和关键 Playwright 流程全部通过。
- [ ] AC9：临时目标检测数据集可完成至少一个轻量 YOLO 训练任务，产出可加载的 `best.pt`，并从该模型生成通过格式校验的 ONNX；CPU 环境同时开放真实 FP32 TorchScript/OpenVINO，TensorRT 只在 NVIDIA Worker 上验收。
- [ ] AC10：临时语义分割与关键点数据集可在 CPU Worker 完成一个轻量训练任务，产出可加载 TorchScript，并至少生成通过校验的 ONNX；SDXL 在没有 GPU 或基础模型时必须在入队或执行前明确拒绝，不能登记伪产物。
- [ ] AC11：新建数据集表单不显示任务类型且 API 不要求该字段；已有数据集可无损迁移。导出与训练阶段显示并校验最终确认的数据格式，Worker 不得忽略用户选择。
- [ ] AC12：格式兼容矩阵在共享契约、API 校验、前端控件、队列配置和 Worker 数据物化之间保持一致；每种开放格式至少有结构验证测试和一个真实训练数据加载测试。
- [ ] AC13：线段/折线和椭圆可以绘制、移动、编辑控制点、保存并恢复；图像标签、骨架和 SDXL Caption 可以随文档统一保存、提交和审核，旧标注 API 请求仍然有效。
- [ ] AC14：SDXL Image Folder 包含与入选图片一一对应的 `metadata.jsonl`，缺少已审核主 Caption 的图片不会进入新 SDXL 训练数据；GPU Runner 读取该 Caption，CPU 环境仍明确拒绝 SDXL 训练。
- [ ] AC15：训练指标图在桌面和窄屏下显示左右纵轴刻度，悬浮/点击可读取精确值；混合显示 mIoU/OKS 与 Loss 时使用独立比例尺。

## Out Of Scope For First Product Increment

- Kubernetes、跨节点分布式训练和云厂商 GPU 自动伸缩。
- 多租户计费、企业 SSO、复杂 RBAC 和审批流。
- 多人实时协同标注和标注冲突自动合并。
- 第一阶段内置所有训练框架实现；通过执行器接口逐类接入真实算法容器。
- 企业版商业闭源授权、闭源 YOLO 执行器和规避 AGPL 源码义务的交付模式。

## Technical Notes

- 首个可运行增量优先支持单机开发和内网部署，使用 PostgreSQL 持久化领域数据、S3 兼容对象存储保存文件、Redis 作为任务队列；真实训练和转换通过 Worker 执行器接口接入。
- 首版保持单工作空间，不实现登录和复杂权限，但所有领域记录预留 workspace 边界，避免后续迁移数据模型。
- 数据集类型列迁移为可空，历史值原样保留用于审计但不再参与训练兼容性判断；新建数据集不写该字段，前端按通用数据集展示。
- 导出只包含所选格式可表达且已经标注/审核的数据；混合几何标注不会因无关几何而污染目标格式。SDXL 保持固定的 Image Folder + prompt 数据契约，不开放检测/分割/关键点格式选择。
- Ultralytics YOLOv5/YOLOv8 按 AGPL-3.0 集成；仓库需提供 LICENSE、第三方依赖与模型权重来源清单，部署包需保留许可证文本和源码获取方式。
- GPU 训练默认使用 FP16 和按模型可选的梯度检查点；SDXL 提供 LoRA 与 DreamBooth LoRA 的低显存配置，不承诺在 T4 16GB 上执行 SDXL 全参数微调。
