# 重新设计数据中心数据树

## Goal

将数据中心重构为按任务目录展示已审核通过数据集的数据树，并补齐全局任务类型管理能力

## Confirmed Repository Facts

- `/datasets` 对管理员渲染 `DataCenterPlaceholderPage`，当前只有标题和空内容区域；审核员/标注员仍渲染 `DatasetsPage` 的平面列表（`src/App.tsx:41-45`、`src/pages/DataCenterPlaceholderPage.tsx:3-9`）。
- `GET /api/v1/datasets` 返回当前工作空间数据集；标注员还会按 `annotatorIds` 做访问过滤（`server/api.ts:285-289`）。
- 数据集状态目前只有 `标注中`、`待审核`、`可训练`；服务端会根据图片审核状态刷新该状态，`可训练` 表示全部图片审核通过（`shared/contracts.ts:204-222`、`server/repository.ts:1042-1043`、`docs/USER_GUIDE.md:62-70`）。
- 当前数据集是任务中立的通用容器；新建数据集写入 `type = NULL`，历史类型只作为 `legacyType` 返回，不用于训练兼容性判断（`server/repository.ts:1044-1052`、`db/migrations/008_task_neutral_datasets_and_formats.sql:1-24`）。
- 当前训练类型是目标检测、语义分割、关键点检测和 SDXL；`YOLO_SEGMENTATION` 属于语义分割训练格式，当前没有独立的实例分割或车道线任务类型（`shared/contracts.ts:4-22`）。
- 数据集已有名称、版本、说明、图片数、已标注数、类别、大小、更新时间和处理配置等字段，但没有明确的业务任务分类字段（`shared/contracts.ts:204-222`、`server/repository.ts:661-663`）。

## Initial Product Intent

- 数据中心以树形层级展示任务大类，用户可展开大类查看其下的任务类型和已完成数据集。
- 目标大类暂定为：目标检测、语义分割、关键点检测、实例分割（用户原文“实力分割”按“实例分割”理解）、车道线检测。
- 展示重点是“标注完成且审核通过”的数据集，而不是继续标注、待审核或未完成的数据集。

## Confirmed Product Boundary

- 用户已确认五个大类是系统正式任务类型，而不是仅用于数据中心展示。
- 正式业务任务成为数据集创建、分类、数据库迁移和权限/API 校验的契约；不改变现有标注几何或审核规则。
- 新增实例分割和车道线大类不自动新增模型或 Worker 能力；按后续确认的边界，训练/导出独立选择并校验兼容性。
- 用户已确认“任务类型”是管理员维护的业务任务，一个数据集绑定一个正式任务类型。数据中心建议采用“任务大类 → 业务任务 → 已审核数据集”的三级树形结构。
- 用户已确认任务类型目录采用“停用代替删除、编码不可变”的生命周期规则：已被数据集使用的任务类型不物理删除；可修改名称和排序或停用；停用后不能创建新数据集，但历史数据仍可查看、审核和导出。
- 用户已确认历史数据不做自动回填或人工补齐；上线迁移时全量删除当前已有数据集及其关联资源，不创建历史默认业务任务。
- 用户明确不按正式任务类型约束标注集合/标注几何。任务类型不强制绑定矩形框、掩码、关键点、实例多边形或折线等工具；标注工具可继续按项目实际需要使用。
- 用户确认任务类型只负责业务分类和数据树归属；训练/导出独立选择模型与数据格式，服务端根据实际标注内容执行兼容性校验，不允许导出无法表达当前标注内容的格式。
- 用户确认新树形数据中心仅面向管理员；审核员和标注员继续使用现有平面任务/标注工作流页面。数据中心定位为管理员查看已审核数据资产的目录，不承担领取标注或审核任务。
- 用户确认数据中心的时间筛选使用数据集创建时间。搜索条件至少包含创建时间范围、任务大类和业务任务类型，并由服务端执行筛选以支持分页和索引。
- 用户确认本次暂不处理 `标注中`、`待审核` 和未完成任务类型迁移的数据集；正式数据树只查询已标注完成且审核通过（`可训练`）且已绑定正式任务类型的数据集，不增加待处理统计入口。
- 用户确认点击数据集叶子节点后打开只读详情，展示任务大类/业务任务类型、名称、版本、创建时间、图片与标注统计、类别数、审核完成时间和存储大小，并复用已有导出/下载入口；数据中心不直接进入标注或审核流程。
- 用户确认任务类型目录不按工作空间隔离，采用全系统共享目录。任务类型编码需要全局唯一，所有数据集都从同一套启用目录中绑定；名称、排序、停用等目录变更会影响全系统展示和新建数据集校验。
- 用户确认全局任务类型目录沿用现有管理员角色维护，不新增平台级管理员角色；任一管理员都可创建、编辑名称/排序和停用全局任务类型。
- 一级任务大类拟采用管理员可配置设计：系统预置目标检测、语义分割、关键点检测、实例分割、车道线检测五个初始大类，管理员可新增、修改名称/说明/排序和停用；大类编码全局唯一且不可修改，预置或自定义大类均不物理删除。停用的大类不能用于新建业务任务或绑定新数据集，但已绑定数据集仍可在历史数据树中查看和导出。由于训练/导出独立按实际标注内容校验，新增大类不自动等同于新增模型执行能力。
- 用户确认预置大类遵循与自定义大类相同的生命周期：名称、说明和排序可修改，编码不可修改，不物理删除，停用后保留历史数据关联。
- 用户确认新建数据集时必须绑定一个启用中的业务任务。已开始标注或已审核的数据集允许管理员改绑，但必须二次确认并写入审计日志。
- 用户确认类型筛选采用两级联动：先选任务大类，再选该大类下的业务任务；接口支持 `categoryCode` 和 `taskTypeCode`，树节点计数与筛选结果一致。
- 用户明确不考虑工作空间边界：数据中心按全系统范围查询数据集，管理员看到统一数据树，不按 `workspaceId` 过滤；任务类型目录和数据集关联也采用全局范围。
- 用户确认数据中心采用服务端聚合 + 数据集分页加载：接口返回筛选后的数据集结果及大类/业务任务聚合计数，前端按三级树展开，数据集叶子节点分页或加载更多。
- 用户确认历史数据不做自动迁移，不创建“历史迁移”默认业务任务，改为在上线迁移时全量删除当前系统已有数据集。当前数据库核查到 2 个没有正式任务类型的数据集，均为 `可训练` 状态；两者及其关联记录、受管制品目录都纳入清理范围，并保留删除审计记录。该清理仅作为实施迁移步骤记录，规划阶段不执行。
- 用户确认不预置业务任务；系统只提供五个初始一级大类，具体业务任务由管理员新增，创建数据集前必须已有可用业务任务。
- 用户确认大类和业务任务编码由系统自动生成，服务端必须校验全局唯一；编码生成后不可修改，管理员维护名称、说明、排序和启用状态。
- 用户确认编码采用服务端生成的“规范化名称 + 随机后缀”短唯一形式，名称修改不重算编码；数据库建立唯一约束，管理详情可查看编码。
- 用户确认同一任务大类下业务任务名称唯一，停用任务的名称也保留占用；不同大类下可存在同名业务任务，使用父级大类和稳定编码区分。
- 用户确认树节点统计显示数据集数量：一级大类和二级业务任务按当前筛选条件统计数据集数，数据集叶子节点显示图片数、标注数等资产摘要。
- 用户确认创建时间筛选包含结束日期：查询使用开始日期当天零点至结束日期次日零点之前的半开区间；仅填写一侧时另一侧不设边界。
- 停用的大类或业务任务仍保留历史数据关联，数据中心继续展示已有数据并标记“已停用”；停用只禁止新建和新绑定，不隐藏历史资产。
- 用户确认管理员可在数据中心数据集详情中修改业务任务绑定：只能选择启用中的业务任务，提交前二次确认，保存后记录审计日志并立即刷新数据树归属；数据集其他字段和标注内容保持只读。
- 用户确认任务类型目录管理页面采用两级目录同页布局：左侧维护任务大类，右侧维护选中大类下的业务任务；两级目录分别支持新增、编辑、排序和停用，业务任务显示关联数据集数量。

## Blocking Open Question

无。核心产品边界已确认，可以进入技术方案设计。

## Acceptance Criteria

- 管理员可在全局任务类型目录中维护大类和业务任务；编码唯一且不可修改，删除通过停用完成，名称/说明/排序可修改。
- 新建数据集必须绑定启用中的业务任务；上线迁移时全量删除当前已有数据集及其关联资源，不做自动回填；管理员改绑需要二次确认并记录审计日志。
- 数据中心仅管理员可访问，展示全系统范围内状态为 `可训练` 且已绑定正式任务类型的数据集，树结构为“任务大类 → 业务任务 → 数据集”。
- 数据中心支持按数据集创建时间范围、任务大类和业务任务类型筛选；两级类型筛选联动，筛选后的树节点计数与数据集结果一致。
- 点击数据集叶子节点打开只读详情，展示任务类型、名称、版本、创建时间、图片/标注统计、类别数、审核完成时间和存储大小，并复用现有导出/下载入口。
- 数据集详情允许管理员修改业务任务绑定；只能选择启用中的任务，二次确认后写入审计日志并刷新树归属，其他数据集字段和标注内容保持只读。
- 停用的大类或业务任务仍展示已有数据并标记“已停用”；停用只影响新建和新绑定，不隐藏历史资产。
- 系统上线迁移时全量删除当前已有数据集及其关联数据库记录和受管制品目录，并记录删除审计；规划阶段不执行该清理。
- 任务类型管理页面采用大类/业务任务两级目录布局，并展示业务任务关联数据集数量。
- 训练和导出继续独立选择模型与格式，服务端按实际标注内容做兼容性校验；任务类型本身不限制标注集合。
