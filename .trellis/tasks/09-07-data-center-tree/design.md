# 数据中心数据树设计

## 1. Domain Model

系统增加全局任务目录，不按 workspace 隔离：

```text
任务大类(category)
  └── 业务任务(task type)
        └── 数据集(dataset)
```

- 大类和业务任务都有服务端生成的稳定编码，编码由规范化名称加随机后缀组成，并由数据库唯一约束保证不重复。
- 编码创建后不可修改；名称、说明、排序和启用状态可修改。
- 删除统一为停用。停用节点不能用于新建业务任务或绑定新数据集，但保留历史关联并在数据树标记“已停用”。
- 系统只预置五个大类：目标检测、语义分割、关键点检测、实例分割、车道线检测；不预置业务任务。
- 一个数据集绑定一个业务任务。新建数据集必须选择启用中的业务任务；管理员可以在详情中改绑，需二次确认并写入审计日志。
- 任务类型只负责业务分类和数据树归属，不约束标注工具。训练和导出仍独立选择模型与格式，并按实际标注内容做兼容性校验。

## 2. Database Changes

新增全局目录表：

`task_categories`

- `id`, `code`, `name`, `description`, `sort_order`, `enabled`, `created_at`, `updated_at`
- `code` 唯一；初始大类与自定义大类遵循相同规则，不增加行为无差异的内置标记。

`task_types`

- `id`, `category_id`, `code`, `name`, `description`, `sort_order`, `enabled`, `created_at`, `updated_at`
- `code` 全局唯一；`(category_id, name)` 唯一，停用名称继续占用。
- `category_id` 外键指向 `task_categories`，不包含 `workspace_id`。

扩展 `datasets`：

- `task_type_id` 非空外键，数据集只保存业务任务关系，大类通过关联查询得到。
- `created_at` 用于数据中心时间筛选。
- `approved_at` 在数据集进入 `可训练` 时写入，用于详情展示；重新开放审核后清空，重新完成审核时更新。
- 删除旧的 `type`/`legacyType` 契约，避免继续把历史三类字段当作正式类型。
- 索引：`(task_type_id, created_at DESC, id) WHERE status = '可训练'`、`(created_at DESC, id)`。

全量清理由独立运维脚本完成，文件移入不对外提供访问的恢复目录，数据库保留审计。SQL 迁移只更新结构；025 在存在未分类数据集时拒绝执行，不自动删除数据。

## 3. API Contract

### Task catalog

- `GET /api/v1/task-categories`：管理员读取全局目录及业务任务关联数量。
- `POST /api/v1/task-categories`、`PATCH /api/v1/task-categories/:id`：创建、编辑、排序、停用大类。
- `POST /api/v1/task-categories/:id/task-types`、`PATCH /api/v1/task-types/:id`：创建、编辑、排序、停用业务任务。
- 所有写操作只允许 `admin`，名称唯一性、启用状态由服务端校验；有关联的数据也允许停用，不做物理删除。

### Data center

- `GET /api/v1/data-center/tree` 只允许管理员，查询全系统数据，不按 `workspaceId` 过滤。
- 查询参数：`from`、`to`、`categoryCode`、`taskTypeCode`、`page`、`pageSize`，可选数据集名称/版本关键词。
- 固定过滤：`status = '可训练'` 且 `task_type_id IS NOT NULL`。
- 返回筛选后的大类聚合、业务任务聚合、数据集分页结果和总数；聚合数量与叶子结果使用同一筛选条件。
- 日期使用半开区间：`created_at >= from 00:00:00`，`created_at < to + 1 day 00:00:00`。

### Dataset binding

- 新建数据集请求必须包含 `taskTypeId`，服务端只接受启用中的业务任务。
- `PATCH /api/v1/datasets/:datasetId/task-type` 只允许管理员，接收目标任务和当前任务版本/确认信息，防止并发覆盖；成功后写 `dataset.task_type.update` 审计记录。
- 数据集详情返回大类、业务任务、创建时间和审核完成时间；详情中的导出/下载继续复用现有接口。

## 4. Frontend Behavior

- `/datasets` 管理员改为新的数据中心树页面；审核员和标注员继续使用现有任务工作流。
- 顶部筛选栏提供创建时间范围、任务大类和业务任务两级联动，结束日期包含当天；重置筛选后重新请求首屏聚合和数据集。
- 树节点显示“任务大类 → 业务任务 → 数据集”。大类和业务任务显示筛选后的数据集数量；数据集叶子显示名称、版本、创建时间、图片数、标注数和大小。
- 大类和业务任务采用按需展开；叶子数据集分页或加载更多，避免一次性返回完整树。
- 停用节点仍可展示历史数据，并显示“已停用”；默认新建/筛选选项只列启用任务，历史查询可以命中停用关联。
- 点击数据集打开只读详情，提供现有导出/下载入口，并提供管理员“修改业务任务”操作。改绑弹出二次确认，保存后刷新当前树路径。
- “系统管理”增加任务目录管理区域：左侧大类列表，右侧选中大类下的业务任务；两级目录支持新增、编辑、排序、停用，并显示业务任务关联数据集数量。
- 数据集创建表单增加业务任务必选项；没有启用业务任务时阻止创建并提示管理员先维护目录。

## 5. Compatibility Boundary

任务目录不会扩展现有 `TrainingType` 枚举，也不会因为新增实例分割或车道线大类就自动创建训练 Worker。训练向导和导出中心继续依据用户选择的模型、格式以及实际标注几何执行兼容校验；任务目录只作为业务分类和审计上下文。

## 6. Migration and Cleanup

1. 发布前运行一次受控清理命令，删除当前全部数据集及其图片、标注、任务段、审核、导出、训练快照和受管制品目录，并写入批量清理审计记录。
2. 执行 SQL migration：创建目录表、预置五个大类、扩展数据集字段、建立唯一约束和查询索引，删除旧类型约束。
3. 部署新的 API 和前端；新建数据集从此强制绑定业务任务。
4. 清理命令需要明确的运维入口和执行结果摘要，避免普通服务启动时重复清理。

## 7. Verification

- 数据库：编码唯一、同一大类下业务任务名称唯一、停用名称不可复用、外键和非空约束。
- API：管理员权限、全局查询、日期边界、两级筛选、聚合计数、分页、停用历史任务、改绑审计。
- 前端：管理员路由、筛选联动、树展开、加载更多、详情、改绑确认、任务目录管理和空目录提示。
- 回归：审核员/标注员原有任务列表与标注入口不受影响；训练/导出格式兼容性测试继续通过。
