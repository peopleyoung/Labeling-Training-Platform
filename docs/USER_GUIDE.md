# 工业视觉训练平台使用说明

本文档面向数据标注人员、算法工程师和平台管理员，说明当前系统中的数据管理、标注审核、模型训练、模型管理和模型转换操作。

## 1. 系统入口与账号

在浏览器中打开平台地址：

```text
http://服务器地址:Web端口
```

使用管理员提供的账号密码登录。系统采用企业内网单租户工作空间，账号登录后访问同一套数据、训练任务、模型和转换任务。

| --- | --- | --- | --- |

页面会根据当前角色隐藏或禁用无权限操作。登录状态失效后重新登录即可。

## 2. 推荐工作流程

1. 在数据中心创建通用数据集并上传图片。
2. 进入标注工作台，维护类别并完成图形或 SDXL 文本标注。
3. 保存全部标注并提交审核。
4. 管理员或算法工程师通过全部图片的审核，使数据集进入“可训练”状态。
5. 根据用途导出数据，或在训练中心选择任务类型和数据格式创建训练任务。
6. 在训练详情查看进度、指标、日志和资源占用。
7. 训练成功后，在模型仓库管理模型版本。
8. 在转换中心生成 ONNX、TorchScript、OpenVINO 或 TensorRT 产物并下载。

数据集创建时不绑定任务类型。目标检测、语义分割、实例分割、关键点或 SDXL 的数据格式在导出和训练时选择。

### 2.1 功能边界

- 训练和模型转换是由部署服务器 Worker 执行的真实任务，浏览器只负责配置、监控和下载产物。
- 平台负责数据标注、审核、数据导出、模型训练、模型登记和格式转换。
- 平台不提供在线推理页面、推理 API 服务或服务发布管理。
- 适用 RK 的模型输出为 ONNX，平台不生成 RKNN 文件，也不执行目标设备侧量化和编译。

## 3. 工作台

工作台提供当前工作空间的总览：

- 数据集数量及待审核数量
- 训练任务状态
- 模型数量
- 转换任务状态
- 最近操作形成的近期活动

近期活动由系统审计记录生成，包括登录、创建数据集、上传图片、保存和审核标注、创建训练、上传模型、创建转换和删除资源等操作。列表为空时，可先执行一次数据集创建或标注保存，再刷新页面确认。

## 4. 数据中心

### 4.1 创建数据集

1. 打开左侧导航中的“数据中心”。
2. 点击“新建数据集”。
3. 填写数据集名称、版本和说明。
4. 确认创建。

数据集名称用于业务识别，版本用于区分数据内容。创建时无需选择任务类型。

### 4.2 上传图片

创建完成后，在数据集操作区上传图片。当前上传要求：

- 支持 JPEG、PNG、WebP。
- 单张图片不超过 50 MB。
- 可一次选择多张图片，前端逐张上传并显示结果。
- 图片文件保存在部署服务器，不使用访问网页电脑的计算或存储目录进行训练。

上传后，数据集进入“标注中”状态。若上传失败，先确认图片格式、文件大小、网络连接和服务器磁盘空间。

### 4.3 数据集状态

| 状态 | 含义 | 可执行操作 |
| --- | --- | --- |
| 标注中 | 存在草稿、未标注或被驳回的图片 | 标注、保存、提交审核 |
| 待审核 | 存在已经提交但尚未处理的图片 | 查看、通过或驳回 |
| 可训练 | 全部图片审核通过 | 导出数据、创建训练任务 |

数据中心可以按“全部、标注中、待审核、可训练”筛选。列表默认每页 10 条，可切换为每页 20 或 50 条。

### 4.4 类别管理

进入标注工作台后，在标签区域维护数据集类别。创建标注对象前应先建立稳定、含义明确的类别，例如 `scratch`、`dent`、`hole`。

类别名称会写入导出文件和训练数据配置。开始大规模标注后应避免随意调整类别顺序或含义。

## 5. 标注工作台

### 5.1 页面布局

标注工作台由四个区域组成：

- 顶部命令栏：返回、保存全部、撤销、重做、提交审核、图片切换、缩放、设置和全屏。
- 左侧工具栏：选择、矩形、多边形、线段、折线、椭圆、关键点、骨架。
- 中央画布：显示图片和标注对象，图片加载后默认居中。
- 右侧面板：对象列表、属性、SDXL 文本标注和标注进度。

系统会加载当前图片已保存的标注。切换图片时，当前编辑内容保留在页面草稿中；点击“保存全部”会统一提交所有已修改图片。

### 5.2 标注工具

| 工具 | 适用场景 | 操作方式 |
| --- | --- | --- |
| 选择 | 选择、移动、调整对象 | 点击对象；拖拽对象移动；拖拽控制点改变大小或形状 |
| 矩形 | 目标检测框 | 按住鼠标拖拽形成矩形 |
| 多边形 | 不规则区域、分割轮廓 | 逐点点击，按 Enter 完成 |
| 线段 | 裂纹、边缘等两点结构 | 点击起点和终点 |
| 折线 | 曲线缺陷、连续轮廓 | 逐点点击，按 Enter 完成 |
| 椭圆 | 圆形或椭圆形缺陷 | 按住鼠标拖拽形成椭圆 |
| 关键点 | 单个定位点 | 点击目标位置 |
| 骨架 | 多关键点结构 | 按定义顺序逐点点击，按 Enter 完成 |

标注坐标按图片归一化保存，因此缩放画布不会改变标注在原图中的位置。对象列表支持选中、隐藏和锁定；锁定后对象不会被误移动。

### 5.3 画布缩放和图片切换

- 使用顶部缩放控件放大或缩小图片。
- 将鼠标放在画布上，按住 `Ctrl` 或 `Command` 并滚动鼠标滚轮，以鼠标位置为中心缩放。
- 缩放范围为 25% 到 400%。
- 使用顶部上一张、下一张按钮切换图片。
- 图片切换不会自动提交到服务端，完成工作后仍需点击“保存全部”。

### 5.4 快捷键

快捷键在焦点不位于输入框、下拉框或文本框时生效。

| 快捷键 | 功能 |
| --- | --- |
| `V` 或 `1` | 选择工具 |
| `R` 或 `2` | 矩形框 |
| `P` 或 `3` | 多边形 |
| `L` 或 `4` | 线段 |
| `N` 或 `5` | 折线 |
| `E` 或 `6` | 椭圆 |
| `K` 或 `7` | 关键点 |
| `S` 或 `8` | 骨架 |
| `A` 或 `←` | 上一张图片 |
| `D` 或 `→` | 下一张图片 |
| `Home` | 第一张图片 |
| `End` | 最后一张图片 |
| `Enter` | 完成多边形、折线或骨架 |
| `Delete` 或 `Backspace` | 删除选中对象 |

### 5.5 稳定绘制建议

- 等待图片和已保存标注加载完成后再开始绘制。
- 先选择类别，再选择标注工具。
- 矩形和椭圆需要有明确拖拽距离，过小的图形不会创建。
- 绘制多边形时至少创建 3 个点；折线至少创建 2 个点。
- 需要连续创建同类对象时，确认工具仍处于激活状态。
- 对象重叠时可从右侧对象列表准确选择，再移动或调整控制点。
- 离开标注页前查看保存状态；存在未保存修改时，页面会提示确认。

### 5.6 SDXL 文本标注

每张图片都可以同时维护 SDXL 训练属性：

1. 打开右侧“SDXL”标签页。
2. 打开“纳入训练”开关。
3. 填写主 Caption。
4. 选择 Caption 语言。
5. 按需填写以英文逗号分隔的图像标签。
6. 点击“保存全部”。

纳入 SDXL 训练的图片必须填写主 Caption。Caption 应描述画面内容、缺陷类型、材质、视角和光照条件，不应包含与图片不符的信息。导出 `Image Folder + Prompt` 时，图片标签和 Caption 会写入 `metadata.jsonl`。

### 5.7 保存、提交和冲突处理

“保存全部”会统一保存当前数据集中所有在本次操作中修改的图片，而不仅是屏幕上正在显示的一张。

每张标注文档带有修订号。当另一浏览器窗口已经保存了同一图片的新内容时，系统会阻止覆盖并提示冲突。出现冲突后应刷新已保存内容，确认差异后重新编辑。

“提交审核”会先保存修改，再把可提交的标注从草稿改为待审核。待审核和已通过的图片处于只读状态，避免审核过程中继续变化。

## 6. 标注审核

管理员和算法工程师可以从数据中心的“审核标注”进入审核模式。

审核时可以：

- 查看当前图片的对象、类别、位置和 SDXL 文本。
- 通过当前图片。
- 驳回当前图片并填写原因。
- 批量通过全部待审核图片。
- 批量驳回全部待审核图片。

驳回必须填写审核意见。被驳回的图片恢复为可编辑状态，标注人员修改并保存后可以再次提交。

只有全部图片都审核通过，数据集才会成为“可训练”。训练和导出都会在服务端再次检查该状态。

## 7. 数据导出

在数据中心选择“可训练”的数据集，点击下载图标打开导出窗口。选择目标格式、导出范围、版本名称以及是否包含原图，然后创建导出任务。

### 7.1 支持格式

| 用途 | 格式 | 标注要求 |
| --- | --- | --- |
| 目标检测 | YOLO | 矩形框 |
| 目标检测 | COCO | 矩形框 |
| 目标检测 | VOC | 矩形框 |
| 语义分割 | COCO Segmentation | 多边形区域 |
| 语义分割 | PNG Mask | 多边形区域和类别 |
| 实例分割 | YOLO Segmentation | 多边形实例 |
| 关键点检测 | COCO Keypoints | 编号关键点；每张图片一个实例 |
| SDXL | Image Folder + Prompt | 已开启“纳入训练”并填写主 Caption |

导出任务只收集审核通过且与所选格式匹配的已标注图片。没有标注、没有主 Caption或标注类型不兼容的图片不会进入导出包。

导出完成后下载 ZIP。导出包包含数据文件、类别信息和 `manifest.json`；选择“包含原图”时同时包含符合条件的图片。

## 8. 训练中心

训练中心列表显示任务名称、模型版本、任务类型、模型、数据集、进度、状态和时间。列表默认每页 10 条，可切换为 20 或 50 条。

### 8.1 创建训练任务

点击“新建训练任务”，按四步向导操作：

1. 选择任务类型。
2. 选择数据集、数据格式、基础模型、架构变体和权重来源，并填写任务名称与模型版本。
3. 配置训练轮次、批次、学习率、输入尺寸、计算设备、混合精度和早停。
4. 检查配置并创建任务。

向导只显示“可训练”的数据集。模型版本必填，训练成功后以该名称和版本登记到模型仓库。

### 8.2 任务与数据格式

| 任务类型 | 可选数据格式 |
| --- | --- |
| 目标检测 | YOLO、COCO、VOC |
| 语义分割 | COCO Segmentation、PNG Mask |
| 实例分割 | YOLO Segmentation |
| 关键点检测 | COCO Keypoints |
| SDXL 微调 | Image Folder + Prompt |

训练只使用与任务格式兼容、已审核通过并位于训练分片中的图片。关键点数据当前按每张图片一个实例组织。

### 8.3 可选模型

| 任务 | 模型 |
| --- | --- |
| 目标检测 | YOLOv5u N/S/M/L/X、YOLOv8 N/S/M/L/X |
| 语义分割 | SegFormer B0-B5、U-Net、DeepLabV3+ ResNet50/101、MobileNetV2、MobileNetV2 RK、MobileNetV3-Large |
| 实例分割 | YOLOv8-Seg N/S/M/L/X |
| 关键点检测 | YOLOv8-Pose N/S/M、HRNet W32/W48、HigherHRNet W32/W48 |
| SDXL | SDXL 1.0 LoRA、SDXL 1.0 DreamBooth LoRA |

SegFormer、U-Net、DeepLabV3+、HRNet 和 HigherHRNet 可选择预训练权重或从头训练。YOLO 系列使用 Ultralytics 权重体系。SDXL 必须使用服务器预置的 SDXL Base 模型。

### 8.4 通用结构与适用 RK 结构

模型向导会显示“通用结构”或“RK 友好结构”：

- YOLOv5u、YOLOv8、YOLOv8-Seg、YOLOv8-Pose 标记为适用 RK。
- DeepLabV3+ MobileNetV2 提供通用结构和独立的 MobileNetV2 RK 结构。RK 结构沿用产品模型 ID，实际部署图按 RK3588-Plaform 构造为 `smp.DeepLabV3`：MobileNetV2 尾部为 320 通道，输出 stride 为 8，不包含全尺寸上采样。
- SegFormer、U-Net、DeepLabV3+ 其他主干、HRNet 和 HigherHRNet 使用通用结构。

“适用 RK”表示网络和 ONNX 导出约束面向 Rockchip NPU 工具链设计，不代表平台直接生成 RKNN，也不代表已经在每一种目标设备上完成性能验证。

MobileNetV2 RK 训练输入固定为 RGB stretch，并使用 `(pixel - 127.5) / 127.5` 归一化。训练器只在计算损失和 mIoU 时临时将 logits 双线性插值到标签尺寸；TorchScript/ONNX 产物保持低分辨率 logits，部署端必须按相同契约完成插值和 argmax。

### 8.5 CPU 与 GPU 训练

CPU 模式：

- 任务使用部署服务器的 CPU 和内存。
- 支持目标检测、语义分割、实例分割和关键点真实训练。
- 使用 FP32，不提供 SDXL 训练。
- 建议选择较小模型、较小 batch 和较少轮次进行验证。

GPU 模式：

- 任务使用部署服务器的 NVIDIA GPU。
- 支持全部任务类型和混合精度。
- YOLOv5u、YOLOv8、YOLOv8-Seg、YOLOv8-Pose 可选择 1 张或 2 张 GPU。
- SegFormer、U-Net、DeepLabV3+、HRNet、HigherHRNet 和 SDXL 单个任务使用 1 张 GPU。

浏览器只负责提交配置和展示状态，关闭浏览器不会让服务端训练转移到客户端或自动停止。

### 8.6 训练状态

| 状态 | 含义 |
| --- | --- |
| 排队中 `queued` | 等待 Worker 和计算资源 |
| 运行中 `running` | 正在训练 |
| 已完成 `completed` | 训练成功，模型已登记 |
| 失败 `failed` | 训练进程返回错误 |
| 已取消 `cancelled` | 用户停止任务 |

### 8.7 训练详情和指标

打开任务详情后，页面按约 3 秒间隔获取服务端状态，展示：

- 当前 Epoch、总 Epoch 和总体进度
- 预计剩余时间
- 训练指标曲线及对应数值
- Loss 曲线和右侧纵坐标刻度
- CPU、内存、GPU 利用率、显存和功耗
- 训练事件与日志
- 当前配置和输出模型信息

不同任务显示相应指标，例如检测的 Precision、Recall、mAP，分割的 mIoU、Dice，关键点的关键点指标，以及 SDXL 的 Loss。

### 8.8 失败、取消、重试和删除

- 失败任务可以点击“重新训练”。系统使用相同配置创建新的训练任务，并在名称中标记重试。
- 排队中或运行中的任务可以先取消。
- 排队中或运行中的任务不能直接删除。
- 任务进入已完成、失败或已取消后可以删除。
- Worker 进程结束需要短暂时间；取消后等待状态稳定再删除。

删除训练任务会同时删除训练日志、指标、资源监控数据、训练目录、由该任务生成的模型，以及这些模型关联的转换记录和转换产物。

## 9. 模型仓库

模型仓库集中展示训练生成和手动上传的模型。列表默认每页 10 条，可切换为 20 或 50 条，不展示训练任务内部 ID。

每条模型信息包括：

- 模型名称和版本
- 任务类型和框架
- 评估指标
- 文件大小和创建时间
- 模型阶段：评估中、生产候选、已归档
- 可用格式
- 架构变体和适用 RK 状态

### 9.1 上传模型

点击“上传模型”，填写名称、版本、任务类型、框架和模型阶段，然后选择权重文件。

支持扩展名：

- `.pt`
- `.pth`
- `.onnx`
- `.safetensors`
- `.torchscript`
- `.xml`
- `.bin`

单个模型文件最大 512 MB。平台会保存文件、计算校验信息并登记模型版本。

仅包含 `state_dict` 的自定义 `.pt` 或 `.pth` 文件没有完整网络结构时，平台无法可靠自动转换。需要转换时优先上传完整 ONNX、TorchScript，或使用平台训练生成的可识别模型。

### 9.2 下载和删除

存在模型产物时可直接下载。删除模型会删除模型记录、模型文件以及该模型关联的转换任务和转换产物；来源训练任务记录不会随模型删除。

## 10. 转换中心

转换中心用于把模型仓库中的模型转换为部署格式。任务列表默认每页 10 条，可切换为 20 或 50 条。

### 10.1 创建转换任务

1. 选择源模型和模型版本。
2. 选择目标格式。
3. 选择精度。
4. 选择目标硬件描述。
5. 提交转换任务。

转换由部署服务器上的 Worker 执行，不使用浏览器所在电脑的资源。

### 10.2 格式能力

| 格式 | CPU 模式 | GPU 模式 | 主要用途 |
| --- | --- | --- | --- |
| ONNX | FP32 | FP32、FP16 | 通用 CPU、GPU 和后续工具链 |
| TorchScript | FP32 | FP32、FP16 | PyTorch Runtime |
| OpenVINO | FP32 | FP32、FP16 | Intel CPU、GPU、NPU |
| TensorRT | 不支持 | FP32、FP16 | NVIDIA GPU |

SDXL 模型转换需要 GPU。平台会融合 LoRA，并转换 SDXL 的 UNet 组件；输出不包含完整的图像生成服务。

### 10.3 适用 RK 的 ONNX

对标记为适用 RK 的模型选择 ONNX：

- 使用静态 batch 1。
- 输入布局为 NCHW。
- 使用固定输入尺寸。
- 使用 opset 12 或 13。
- YOLO NMS、分割掩码处理和关键点解码不嵌入模型，由目标端运行时代码执行。

平台输出 ONNX，不输出 RKNN。后续应在目标部署环境使用对应工具链完成量化、编译和设备验证。

适用 RK 状态含义：

| 状态 | 含义 |
| --- | --- |
| `not_reviewed` | 未进行 RK 结构评估 |
| `standard_only` | 通用结构，不承诺 RK 适用性 |
| `rk_structure_ready` | 结构和导出约束已按 RK 路径准备 |
| `onnx_validated` | ONNX 图和数值已通过验证 |
| `device_validated` | 已在目标设备完成验证 |

### 10.4 任务操作

- 排队中和运行中的转换任务可以取消。
- 已完成任务可以下载产物。
- 已完成、失败或已取消的任务可以删除。
- 删除转换任务会删除任务记录、队列记录和转换产物目录。

## 11. 删除资源与磁盘空间

删除操作会处理数据库记录和部署服务器上的对应文件：

| 删除对象 | 同时删除的内容 |
| --- | --- |
| 数据集 | 图片、标注文档、审核数据、导出任务和导出 ZIP |
| 训练任务 | 日志、指标、资源数据、训练产物、生成模型及关联转换产物 |
| 模型 | 模型文件及关联转换记录和产物 |
| 转换任务 | 转换记录和转换产物 |

删除不可恢复。执行前应确认任务、模型版本和下载产物不再需要。活动任务需要先取消，等待 Worker 结束后再删除。

平台模型缓存不随业务资源删除。模型缓存由平台运维人员统一管理，避免删除共享预训练权重导致其他任务无法启动。

## 12. 常见问题

### 12.1 页面无法连接接口

若提示 `Failed to fetch`：

1. 刷新页面并重新登录。
2. 确认浏览器可以访问 API 地址。
3. 联系运维检查 API 服务、端口、防火墙、`CORS_ORIGIN` 和 `VITE_API_BASE_URL`。

### 12.2 图片无法显示或一直加载标注

1. 确认数据集和图片仍然存在。
2. 直接刷新标注页面。
3. 检查浏览器网络面板中的图片和标注接口状态。
4. 联系运维查看 API 日志和 `/data/artifacts/datasets` 文件。

### 12.3 有时画不上标注

1. 等待图片和已保存标注加载完成。
2. 确认不在审核只读模式。
3. 确认已经选择类别和正确工具。
4. 矩形、椭圆应拖出可见尺寸；多边形和折线应满足最少点数。
5. 按 `Esc` 取消未完成图形，再重新选择工具。

### 12.4 数据集不能训练或导出

- 数据集必须显示为“可训练”。
- 所有图片都需要完成提交和审核通过。
- 所选格式必须与标注类型匹配。
- SDXL 图片必须打开“纳入训练”并填写主 Caption。

### 12.5 训练任务一直排队

- CPU 任务需要 CPU Worker 正常运行。
- GPU 任务需要 GPU Worker 正常运行且有空闲资源。
- 模型首次使用时可能正在下载预训练权重。
- 查看任务详情中的事件和日志，或联系运维检查 Worker。

### 12.6 训练失败

优先查看任务详情中的最后一条错误和日志，常见原因包括：

- 训练分片没有符合格式的已审核图片。
- 类别、掩码或关键点定义不完整。
- 预训练权重未下载且服务器不能访问模型源。
- GPU 显存不足，batch 或输入尺寸过大。
- SDXL 基础模型目录不完整。

修正数据或运行环境后点击“重新训练”。

### 12.7 转换失败

- CPU 模式只能选择 FP32 ONNX、TorchScript 或 OpenVINO。
- TensorRT、FP16 和 SDXL 转换需要 GPU。
- 自定义权重需要包含可识别网络结构。
- 适用 RK 的 ONNX 使用固定输入和静态 batch 1。

## 13. 使用建议

- 先用少量图片完成“标注、审核、训练、转换”全流程验证，再扩大数据规模。
- 类别名称、关键点顺序和数据版本命名在标注前确定。
- 使用 `v1.0.0`、`v1.1.0` 等清晰模型版本，避免重复名称造成识别困难。
- CPU 环境先选择 N 或 S 级 YOLO、较小输入尺寸和 batch。
- GPU 训练逐步增大 batch，并持续观察显存和功耗。
- 导出和模型转换完成后及时下载需要交付的产物。
- 删除数据集、任务和模型前确认产物已经备份。
