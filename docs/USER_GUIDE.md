# Forge AI 工业质检训练平台使用说明

本文面向标注员、算法工程师和管理员，说明如何在 Forge AI 中完成从图像导入、标注审核、模型训练到模型转换和产物下载的完整闭环。

> 本文描述的是当前已交付功能。平台暂未提供在线推理页面、实时推理 API 或模型服务发布能力；完成训练和转换后，需要在目标推理环境中自行加载下载的模型产物。

## 1. 开始前准备

### 1.1 访问与登录

在浏览器打开部署地址：`http://<服务器地址>:5174/`。推荐使用最新版 Chrome、Edge 或 Firefox，并保持浏览器可访问部署服务器的 Web 与 API 地址。

初始管理员账号由部署时的 `.env` 文件配置：

```dotenv
BOOTSTRAP_ADMIN_USERNAME=<管理员账号>
BOOTSTRAP_ADMIN_PASSWORD=<管理员初始密码>
```

首次启动只会创建一次该账号；重启服务不会重置已存在用户的密码。请不要在共享文档、数据集名称或训练日志中记录密码。

### 1.2 角色与权限

| 操作 | 管理员 | 算法工程师 | 标注员 |
| --- | --- | --- | --- |
| 查看数据集、训练、模型和产物 | 是 | 是 | 是 |
| 新建/导入/删除数据集 | 是 | 是 | 否 |
| 保存标注、提交审核 | 是 | 是 | 是 |
| 审核通过或驳回标注 | 是 | 是 | 否 |
| 创建、取消、重试或删除训练任务 | 是 | 是 | 否 |
| 上传模型、变更模型阶段、创建转换 | 是 | 是 | 否 |
| 下载已授权产物 | 是 | 是 | 是 |

### 1.3 支持的计算能力

平台会在工作台和训练向导中显示当前 Worker 能力。

| 部署模式 | 可用能力 |
| --- | --- |
| CPU Worker | 数据集导出；YOLOv5u/YOLOv8、SegFormer/U-Net/DeepLabV3+、HRNet/HigherHRNet 的真实训练；FP32 ONNX、TorchScript、OpenVINO 转换 |
| GPU Worker | 包含 CPU 能力；GPU 训练、TensorRT 转换、SDXL LoRA / DreamBooth LoRA 训练与转换 |

CPU 模式下 SDXL 与 TensorRT 会被明确禁用，不会生成占位产物。CPU 训练适合验证数据和流程，正式大规模训练应使用 GPU Worker。

## 2. 推荐工作流

```text
创建数据集并上传图像
        ↓
绘制标注并保存全部图片
        ↓
提交审核 → 管理员/算法工程师审核通过
        ↓
创建训练任务并监控指标
        ↓
在模型仓库下载原始模型或创建转换任务
        ↓
将 ONNX / TensorRT / TorchScript / OpenVINO 产物部署到目标推理环境
```

数据集的状态含义如下：

| 状态 | 含义 | 下一步 |
| --- | --- | --- |
| 标注中 | 仍有草稿、被驳回图片或未完成的标注 | 继续标注并保存 |
| 待审核 | 标注已提交，等待审核决策 | 管理员或算法工程师审核 |
| 可训练 | 数据集全部图像已审核通过 | 可训练，也可创建正式导出 |

审核通过后再次编辑任意图片，或继续向数据集新增图片，数据集会回到标注中并需要重新审核。

## 3. 创建和导入数据集

1. 进入左侧导航的“数据中心”。
2. 点击“导入数据”或“新建数据集”。两个入口都会打开“新建并导入数据集”。
3. 填写数据集名称、版本、类别和说明。
4. 在“图像文件”选择本地原图，然后点击“创建并上传”。

类别以英文逗号、中文逗号或换行分隔，例如：

```text
scratch, dent, contamination
```

上传约束：

- 仅支持 JPEG、PNG、WebP。
- 单张图像最大 50 MB。
- 当前导入流程只接收原图；外部 YOLO、COCO、VOC 等标注文件不会自动解析。请在平台标注工作台中创建标注，或通过受控 API 集成导入流程。
- 数据集本身不绑定单一任务类型。训练或导出时再选择目标检测、分割、关键点或 SDXL 所需的标准格式。

上传完成后，若至少有一张图片，平台会直接进入该数据集的标注工作台。之后也可在数据中心点击“继续标注”或“查看标注”返回工作台。

## 4. 标注工作台

### 4.1 基本操作

标注工作台由左侧工具栏、中央画布、图片导航和右侧属性面板组成。

1. 在右侧类别区域确认或添加要使用的类别。
2. 从左侧工具栏选择工具，在画布上绘制对象。
3. 选中对象后可移动对象，拖动控制点编辑形状；右侧检查器可查看类别、类型和编辑状态。
4. 用对象行的锁定图标或右侧“锁定”按钮保护已确认对象；隐藏只影响画布查看，不会删除对象。
5. 点击“保存全部”保存当前数据集内全部未保存草稿。可使用 `Ctrl+S`（macOS 为 `Command+S`）。

图片导航支持上一张/下一张按钮，也支持 `A`/左方向键与 `D`/右方向键。离开存在未保存草稿的工作台时，浏览器会要求确认。

### 4.2 标注工具与适用任务

| 工具 | 绘制方式 | 主要用途 |
| --- | --- | --- |
| 矩形框 | 拖拽两个对角点 | 目标检测、粗粒度分割 |
| 多边形 | 连续单击顶点后点击“完成多边形” | 不规则缺陷区域、分割 |
| 线段/折线 | 连续单击至少两个点后完成 | 线状缺陷、轨迹参考 |
| 椭圆 | 拖拽绘制，可编辑控制点 | 圆孔、圆形缺陷区域 |
| 关键点 | 单击图像位置并设置正整数编号 | 姿态、定位点检测 |
| 骨架 | 按关键点构建后完成骨架 | 关键点关系的可视化与标注记录 |

目标检测训练与 YOLO/COCO/VOC 导出使用可表达的矩形框或多边形。语义分割训练将矩形和多边形栅格化为类别掩码。关键点训练只读取带正整数编号的关键点；首版按“每张图一个关键点实例”组织，因此不适用于单图多个独立人体/部件实例的复杂分组场景。

### 4.3 保存、冲突与审核

- 每次保存带有修订号。若另一位用户已更新同一图片，平台会提示版本冲突；先比较服务器版本与当前草稿，再选择加载服务器版本或覆盖保存。
- 完成数据集标注后，点击“提交审核”。提交后图片进入只读状态，直到审核完成。
- 管理员和算法工程师从数据中心选择“审核标注”，进入审核模式后可以逐张通过、逐张驳回或批量处理待审核图片。驳回必须填写原因。
- 标注员可以查看审核状态和驳回原因，修改后重新保存并提交。

不要仅以“画布上有图形”判断数据可训练。应以数据中心显示的“可训练”状态为准；训练与正式导出接口都会拒绝未完全审核的数据集。

### 4.4 SDXL Caption 与图像属性

对要用于 SDXL 微调的图片，在右侧 SDXL 区域完成以下内容：

1. 勾选“纳入 SDXL 训练”。
2. 填写人工“主 Caption”，并选择 `English` 或 `中文`。
3. 可选填写用英文逗号分隔的图像标签。
4. 如需局部训练，开启“训练裁剪区域”，以百分比填写 `X`、`Y`、`WIDTH`、`HEIGHT`。
5. 保存全部并完成审核。

勾选“纳入 SDXL 训练”时主 Caption 为必填项。Image Folder 导出和 SDXL Runner 只会读取已审核、被勾选且有主 Caption 的图片；标签和裁剪区域会一并写入 `metadata.jsonl`。

## 5. 导出标注数据

数据集成为“可训练”后，在数据中心的操作列点击下载图标，打开“导出标注数据”。选择格式、数据范围、版本名称，以及是否包含原图，再点击“创建导出任务”。导出在后台运行，完成后可在同一窗口的导出记录中下载 ZIP。

| 训练用途 | 可选导出格式 | 典型内容 |
| --- | --- | --- |
| 目标检测 | YOLO、COCO、VOC | YOLO 的 `images/`、`labels/`、`dataset.yaml`；COCO JSON；VOC XML |
| 语义分割 | COCO Segmentation、PNG Mask | 多边形 COCO JSON，或类别索引 PNG 掩码与 `classes.json` |
| 关键点 | COCO Keypoints | 包含 `keypoints` 的 COCO JSON |
| SDXL | Image Folder | 已入选图片与逐图 `metadata.jsonl` |

所有导出 ZIP 都会包含 `manifest.json`。以下是典型的 Image Folder 结构：

```text
quality-images-v1.zip
├── images/
│   ├── part-0001.jpg
│   └── part-0002.png
├── metadata.jsonl
└── manifest.json
```

`metadata.jsonl` 每行对应一张图片，包含相对文件名、主 Caption、语言、标签及可选裁剪信息。导出会自动排除未审核、没有标注或与所选格式不兼容的图片；勾选“包含已标注原始图像”才会复制原图到 ZIP。

## 6. 创建训练任务

### 6.1 进入训练向导

从数据中心的“配置训练”或训练中心的“新建训练”进入四步向导。向导只会显示状态为“可训练”的数据集。

1. **任务类型**：选择目标检测、语义分割、关键点检测或 SDXL 微调。
2. **数据与基础模型**：填写任务名，选择数据集版本、标准数据格式、模型及权重来源。
3. **参数与资源**：设置轮次、Batch、学习率、输入尺寸、设备、混合精度和早停。
4. **确认启动**：复核配置后点击“创建并启动”。

### 6.2 任务、格式与模型

| 任务 | 可选数据格式 | 可选模型家族 | 常用质量指标 |
| --- | --- | --- | --- |
| 目标检测 | YOLO、COCO、VOC | YOLOv5u、YOLOv8 | Precision、Recall、mAP@50、mAP@50-95 |
| 语义分割 | COCO Segmentation、PNG Mask | SegFormer、U-Net、DeepLabV3+ | mIoU、Loss |
| 关键点检测 | COCO Keypoints | HRNet、HigherHRNet | OKS、Loss |
| SDXL 微调 | Image Folder | SDXL LoRA、SDXL DreamBooth LoRA | Runner 上报的 Loss 等指标 |

“官方预训练权重”会在首次使用时下载或读取共享缓存；隔离网络应由管理员按部署说明预置权重。选择“从头训练”可避免依赖外部权重，但通常需要更多数据和训练轮次。

### 6.3 参数建议

首次验证一个新数据集时，请优先选择较小模型和保守参数：

| 场景 | 建议起点 |
| --- | --- |
| CPU 目标检测 | `yolov8n` 或 `yolov5n`，输入 640，Batch 1-4 |
| CPU 分割/关键点 | 输入 128-384，Batch 1-4，先验证数据与类别映射 |
| GPU 目标检测 | 从 `yolov8n`/`yolov8s` 和中等输入尺寸开始，再按显存增加 Batch |
| SDXL | GPU Worker、Batch 1、FP16、梯度检查点，以及已预置的 SDXL Base |

CPU 的真实训练可能持续数小时。创建任务前确认没有错误选择过大的输入尺寸、Batch 或模型；任务提交后由 Worker 再次校验数据集、模型、格式和硬件能力。

## 7. 监控、重试与取消训练

训练中心列出全部任务。点击一条任务可进入详情页查看：

- 状态、Epoch、总体进度、预计完成时间和主指标；
- 结构化运行日志与失败原因；
- 质量指标曲线和 CPU/GPU 资源采样；
- 训练产物与生成的模型版本。

指标图的左轴显示 mAP、Precision、Recall、mIoU、OKS 等质量指标，右轴显示 Loss。悬浮或触摸数据点可读取该 Epoch 的精确值，图例可单独开关每个系列。质量指标与 Loss 使用独立比例尺，不能直接比较两者的数值大小。

任务状态：

| 状态 | 说明 | 可执行操作 |
| --- | --- | --- |
| queued | 已入队，等待 Worker | 等待或取消 |
| running | Worker 正在执行 | 监控或取消 |
| completed | 已生成可用产物 | 下载模型、创建转换 |
| failed | 执行、数据或配置校验失败 | 查看日志和错误原因，修正后重新训练 |
| cancelled | 已取消 | 可重新创建任务 |

管理员和算法工程师可以对失败任务执行“重新训练”。系统会复制原始配置并按照当前数据集、模型和 Worker 能力重新校验，原失败记录会保留以便追溯。活动任务不能直接删除，需先取消；完成、失败或已取消任务才允许删除。

## 8. 模型仓库与转换

### 8.1 模型仓库

成功训练会自动登记模型版本。进入“模型仓库”可按任务筛选、查看来源训练任务、最佳指标、已有部署格式和模型阶段。

- 点击下载图标可下载模型产物。
- 可将模型阶段在“评估中”和“已归档”之间切换。
- 管理员或算法工程师可上传 `.pt`、`.pth`、`.onnx`、`.safetensors`、`.torchscript`、`.xml`、`.bin` 文件；单文件上限 512 MB。

手工上传的普通 PyTorch state dict 没有网络结构和模型族血缘，平台无法可靠地自动转换。优先使用平台训练产物、可识别的 YOLO 权重，或直接上传可执行的 ONNX/TorchScript 文件。

### 8.2 创建转换任务

1. 在模型仓库中点击“转换”，或进入“转换中心”。
2. 选择源模型版本、目标格式、精度与目标设备。
3. 必要时启用图优化，复核摘要后点击“创建转换任务”。
4. 在下方转换任务列表等待完成并下载产物。

| 格式 | 常见目标 | CPU 模式 | GPU Worker |
| --- | --- | --- | --- |
| ONNX | 跨平台 Runtime | FP32 | FP32 / FP16 |
| TorchScript | PyTorch Runtime | FP32 | FP32 / FP16 |
| OpenVINO | Intel CPU/GPU/NPU | FP32 | FP32 / FP16 |
| TensorRT | NVIDIA GPU | 不可用 | 可用 |

OpenVINO 产物会以含 `.xml` 和 `.bin` 的 ZIP 包下载。TensorRT engine 与 CUDA、cuDNN、TensorRT 和目标 GPU 高度相关，应在最终部署设备或兼容运行时构建和验证。

## 9. 推理与部署边界

当前版本把“可部署产物”交付给外部推理环境，但不管理在线服务生命周期。

- **ONNX**：使用 ONNX Runtime、TensorRT 或其他兼容推理引擎加载。
- **TorchScript**：使用匹配版本的 PyTorch Runtime 加载。
- **OpenVINO**：使用 OpenVINO Runtime 加载 XML/BIN。
- **TensorRT**：在兼容的 NVIDIA 驱动与 TensorRT 运行时加载 engine。
- **SDXL LoRA**：需与相同或兼容的 SDXL Base 在 Diffusers 等运行环境中加载；转换产物为 UNet 组件，不是完整的文本编码器、VAE 或 Pipeline 包。

部署前应在目标硬件上完成输入预处理、类别索引、阈值、输出后处理、吞吐与延迟验证。平台目前没有“上传图片立即预测”的 UI、推理 REST API、批量推理任务或模型服务发布接口。

## 10. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 无法创建训练或导出任务 | 数据集尚未成为“可训练”。保存全部标注、提交审核，并确保所有图片审核通过。 |
| 提示 `SDXL_CAPTION_REQUIRED` | 图片已勾选纳入 SDXL，但没有主 Caption。填写 Caption 后重新保存。 |
| 提示 `SDXL_GPU_REQUIRED` | 当前只有 CPU Worker。启用 GPU profile、安装 NVIDIA Container Toolkit 并预置 SDXL Base 后再提交。 |
| SDXL 任务失败且无模型产物 | GPU Worker 找不到完整 Diffusers 格式的 Base，或 CUDA 运行条件不满足。按部署说明检查 `/data/model-cache` 与 Worker 日志。 |
| 训练失败 | 在训练详情页读取结构化错误和日志；重点检查已审核样本数、类别、选择的数据格式、权重可用性和硬件容量。 |
| 导出包缺少部分图片 | 未审核、未标注或无法被当前导出格式表达的图片会被排除。查看 `manifest.json` 的统计。 |
| 标注保存冲突 | 另一位用户已修改该图片。保留当前草稿，比较服务器版本后再选择加载或覆盖。 |
| 找不到 TensorRT 选项 | TensorRT 只在 GPU Worker 可用，且必须在匹配的 NVIDIA 环境中转换。 |
| 无法访问页面或登录失败 | 检查部署地址、`CORS_ORIGIN`、`VITE_API_BASE_URL`、API 健康检查和账号密码。 |

## 11. 管理员日常检查

管理员应定期检查以下项目：

1. 工作台中的 CPU/GPU Worker 能力是否与部署预期一致。
2. 数据中心是否存在长期“待审核”或“标注中”的数据集。
3. 训练中心是否存在失败或长期排队任务，并查看 Worker 日志。
4. `forge-worker-data` 共享卷可用空间是否足以容纳原图、导出临时包、模型和转换产物。
5. PostgreSQL、MinIO 与 Worker 产物卷是否按 [部署说明](DEPLOYMENT.md) 完成备份。
6. 账号、JWT 密钥、数据库与 MinIO 密码是否按内网安全规范管理。

部署、GPU 启用、模型预置、备份恢复、升级和容器级故障排查，请参阅 [部署说明](DEPLOYMENT.md)。
